**特殊标记是人工定义的标记，用于启用模型的特定能力，例如「中间填充（fill-in-the-middle）」。**

So we want to be careful about accidentally encoding special tokens, since they can be used to trick a model into doing something we don't want it to do.
**因此我们必须小心，避免意外编码特殊标记；这类标记有可能被用来诱导模型执行非预期行为。**

Hence, by default, encode will raise an error if it encounters text that corresponds to a special token.
**所以默认行为：当 encode 函数遇到文本匹配特殊标记时，会抛出报错。**

This can be controlled on a per-token level using the `allowed_special` and `disallowed_special` parameters.
**可以通过 `allowed_special` 和 `disallowed_special` 参数，按单个标记粒度控制该行为。**

In particular:
**具体规则：**

- Setting `disallowed_special` to `()` will prevent this function from raising errors and cause all text corresponding to special tokens to be encoded as natural text.
  - 将 `disallowed_special` 设置为 `()`，函数不会抛出异常，所有匹配特殊标记的文本都会被当作普通自然文本编码。
- Setting `allowed_special` to `"all"` will cause this function to treat all text corresponding to special tokens to be encoded as special tokens.
  - 将 `allowed_special` 设置为 `"all"`，函数会把所有匹配特殊标记的文本，直接编码为特殊标记。

# json.dump
# Python json.dump 文档｜中英对照
> `json.dump(obj, fp, ...)`
```
Serialize ``obj`` as a JSON formatted stream to ``fp`` (a ``.write()``-supporting file-like object).
```
将 `obj` 序列化为 JSON 格式流，写入 `fp`（支持 `.write()` 的类文件对象）。

```
If ``skipkeys`` is true then ``dict`` keys that are not basic types (``str``, ``int``, ``float``, ``bool``, ``None``) will be skipped instead of raising a ``TypeError``.
```
若 `skipkeys=True`：字典里非基础类型（str/int/float/bool/None）的键会被直接跳过，而不是抛出类型错误`TypeError`。

```
If ``ensure_ascii`` is false, then the strings written to ``fp`` can contain non-ASCII characters if they appear in strings contained in ``obj``. Otherwise, all such characters are escaped in JSON strings.
```
若 `ensure_ascii=False`：写入文件的字符串可以保留非ASCII字符（例如中文）；否则所有非ASCII字符都会被转义。

```
If ``check_circular`` is false, then the circular reference check for container types will be skipped and a circular reference will result in an ``RecursionError`` (or worse).
```
若 `check_circular=False`：跳过容器类型的循环引用检测；一旦存在循环引用，会触发递归错误`RecursionError`（甚至更严重问题）。

```
If ``allow_nan`` is false, then it will be a ``ValueError`` to serialize out of range ``float`` values (``nan``, ``inf``, ``-inf``) in strict compliance of the JSON specification, instead of using the JavaScript equivalents (``NaN``, ``Infinity``, ``-Infinity``).
```
若 `allow_nan=False`：严格遵循JSON标准，序列化`nan / inf / -inf`这类超限浮点数时抛出`ValueError`，而不是输出JS风格的`NaN/Infinity`。

```
If ``indent`` is a non-negative integer, then JSON array elements and object members will be pretty-printed with that indent level. An indent level of 0 will only insert newlines. ``None`` is the most compact representation.
```
若`indent`为非负整数：JSON数组与对象会按该缩进值做美化输出。`indent=0`仅换行；`indent=None`为最紧凑压缩格式。

```
If specified, ``separators`` should be an ``(item_separator, key_separator)`` tuple. The default is ``(', ', ': ')`` if *indent* is ``None`` and ``(',', ': ')`` otherwise. To get the most compact JSON representation, you should specify ``(',', ':')`` to eliminate whitespace.
```
如果传入`separators`，必须是`(元素分隔符,键值分隔符)`元组。
- `indent=None`（压缩模式）默认：`(', ', ': ')`
- 有缩进时默认：`(',', ': ')`
想要极致压缩JSON，设置 `separators=(',', ':')`，消除全部多余空格。

```
``default(obj)`` is a function that should return a serializable version of obj or raise TypeError. The default simply raises TypeError.
```
`default(obj)`：回调函数，需要返回obj可序列化版本，或者抛出`TypeError`。内置默认实现直接抛`TypeError`。

```
If *sort_keys* is true (default: ``False``), then the output of dictionaries will be sorted by key.
```
`sort_keys=True`（默认False）：字典输出会按键名排序。

```
To use a custom ``JSONEncoder`` subclass (e.g. one that overrides the ``.default()`` method to serialize additional types), specify it with the ``cls`` kwarg; otherwise ``JSONEncoder`` is used.
```
如需自定义`JSONEncoder`子类（例如重写`.default()`来序列化更多类型），使用`cls`关键字参数指定；否则使用默认`JSONEncoder`。

# ✅ dumps vs dump 核心对比（面试必考）
1. `json.dumps()` → **dumps = dump string**：输出JSON字符串，存内存，后续可自行写入文件。
2. `json.dump()` → **dump to file**：直接写入类文件对象`fp`，不返回字符串。
> 参数列表几乎完全一致，行为差异仅在于输出目标。

## 面试英文口述版（可直接背诵）
`json.dumps` serializes Python object into a JSON string in memory. `json.dump` writes JSON data directly into a file-like fp stream. They share almost identical parameters. The most commonly used arguments are `ensure_ascii` for unicode control, `indent` for pretty print, `default` for custom object serialization, and `sort_keys` to sort dictionary keys.

## 实操高频坑点小结
1. `ensure_ascii=True` 中文会变成 `\uXXXX`；处理中文场景一般设 `False`
2. 自定义对象序列化：写`default`函数，或者继承`JSONEncoder`通过`cls`传入
3. `nan/inf`不属于标准JSON，`allow_nan=False`会抛异常

# Q: Explain `token_list = [x["token_count"] for x in chunk_result]`
A:This is a **Python list comprehension** (列表推导式).

### Full breakdown

```
token_list = [x["token_count"] for x in chunk_result]
```

**English**

1. `chunk_result`: a list of dictionaries. Each element `x` is one chunk dict like `{"chunk_index":0, "text":"...", "token_count": 120}`
2. `for x in chunk_result`: iterate every dictionary `x` inside `chunk_result`
3. `x["token_count"]`: extract the value mapped by key `"token_count"` from each dict `x`
4. The outer `[]`: collect all extracted values and assemble them into a **new list**, assigned to variable `token_list`.

Equivalent for-loop version (plain verbose code):

```
token_list = []
for x in chunk_result:
    token_list.append(x["token_count"])
```

# Q: but if you want to enumerate or iterate a collection ,why not use x[chunk_index]?
A:### Core confusion

`chunk_result` is a **list of dictionaries**.
`chunk_index` is the ID value stored **inside each dictionary**, NOT the index of the list.

```
# chunk_result structure
chunk_result = [
    {"chunk_index":0, "token_count": 210},  # this is chunk_result[0]
    {"chunk_index":1, "token_count": 450},  # this is chunk_result[1]
    {"chunk_index":2, "token_count": 320},  # this is chunk_result[2]
]
```

**English**
`chunk_result[chunk_index]` means:

> 
> Use the numeric value stored in dict `x["chunk_index"]` as the **list index**, to fetch an element from the `chunk_result` list.

`x["chunk_index"]` means:

> 
> Read the value of the key `"chunk_index"` **inside the current dictionary x** we are iterating.

These two are completely different things.

#### Example of wrong code

```
# ❌ Wrong
token_list = [ chunk_result[x["chunk_index"]]["token_count"] for x in chunk_result ]
```

This works **only when chunk_index exactly matches the list position index**.
But once you filter / skip empty paragraphs, `chunk_index` is your contiguous saved-id, while the list index is always sequential.
If you later shuffle or filter chunks, `x["chunk_index"]` will no longer equal the list index, and this code breaks.

#### Our original correct code

```
# ✅ Correct
token_list = [x["token_count"] for x in chunk_result]
```

We are already looping over each `x` (each dictionary).
We directly extract `token_count` from current `x`. No need to index back into the outer list.
